## 背景
当前 Memory MVP 已经实现基础的记忆候选提取和检索能力。

但是现有设计主要围绕“可检索文本”展开，
无法完整表达 SenaBot 长期陪伴场景下需要维护的用户状态、
关系状态以及角色成长。

因此需要重新明确 Memory 的领域边界，
避免后续功能扩展过程中出现数据模型和职责混乱。

## Memory 定位
Memory 是 SenaBot 对用户、经历、知识以及长期形成理解的认知存储基础，负责维护角色连续性所需的长期信息。它界定对于存储内容的纵向分层以及横向分类，以及如何决定对长期记忆进行什么操作,存储到哪一具体分类部分。同时根据Agent侧传入的内容，决定读取的相关策略


## 当前实现分析
当前已有记忆的写入和读取部分的基础框架,当前框架合理。
## 当前不足
- Memory语义不足
- 生命周期不足
- Scope不明确
- Memory归属关系不足

## 重构范围界定
- 当前数据结构未确定记忆边界和生命周期范围,同时混入部分万能字段,应予以删除和修改。
- 响应时间等非功能性要素影响框架设计,可以予以部分约束和预留接口,但不是本次实现内容。
- 日记、人格、好感度等属于基于 Memory 构建的上层能力，不作为本次 Memory Core 数据模型设计目标。本次设计应保证未来能够基于 Memory 扩展这些能力。。可以提issue作为未来实现,但不应纳入也不应影响本次重构。
- 确认数据库选型以帮助数据结构设计,但不具体实现。
## 目标框架

- 保持当前的写入-读取两条链路不变,但对具体写入方式,内容,链路作多元化分级以及重构。
- 底层采用关系型数据库+Vector DB的模式,关系型数据库储存事实来源,向量数据库负责语义检索
- 检索部分应该以Bot_id作为顶级归属,但不仅仅限于Bot_id。

## 模块边界
- Memory只负责记忆的存储,存储结构,类型,分层,以及存储策略的界定。
- Memory负责长期信息自身的形成、维护和组织，但不负责直接驱动人格、关系状态等角色层面的变化。这样会导致Memory职责过宽,而Agent职责收窄
